\chapter{Технологический раздел}

\section{Средства реализации}

Программа написана на Python~3.12.14. Библиотека Pillow~13.0.0 читает JPEG, извлекает таблицы квантования и позволяет декодировать яркость изображения. Та же библиотека использована при подготовке контрольных JPEG с заданными качеством и цветовой субдискретизацией~\cite{pillow}. Массив яркости и гистограммы обрабатываются средствами NumPy~2.5.5. Функция \texttt{dctn} из SciPy~1.18.1 выполняет ДКП по двум выбранным осям массива, что позволяет обработать все блоки фрагмента одним вызовом~\cite{scipy_dct}.

Обе сети реализованы на PyTorch~2.15.0. При обучении вычисления выполняются на графическом процессоре Apple через MPS~\cite{pytorch_mps}. При запуске классификатора веса загружаются на центральный процессор. Обучение и исследование оформлены в Jupyter Notebook. Для подсчёта метрик используется scikit-learn, для группировки результатов опытов --- pandas, для графиков --- Matplotlib.

\section{Модули и представление данных}

Модуль \texttt{prepare\_data.py} готовит выборки для обучения и оценки моделей. Для DJPEG он сверяет контрольную сумму архива, извлекает выбранные пары и проверяет, что последняя таблица, указанная в имени файла, совпадает с таблицей яркости в заголовке JPEG. Для UCID модуль формирует варианты сжатия и записывает параметры обоих сохранений. Матрицы признаков хранятся отдельно от CSV-таблиц с метками. Строка матрицы и строка соответствующей таблицы относятся к одному изображению.

Модуль \texttt{detector.py} извлекает признаки, задаёт сети и обрабатывает аргументы командной строки. Программа выбирает таблицу по номеру яркостной компоненты, переводит декодер Pillow в режим \texttt{L} и выделяет фрагмент по формуле~\eqref{eq:crop}. Расчёт гистограмм приведён в листинге~\ref{lst:dct}.

\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[language=Python,
 caption={Извлечение гистограмм и присоединение таблицы квантования},
  label={lst:dct}]
blocks = (pixels - 128).reshape(32, 8, 32, 8)
coeff = dctn(blocks, axes=(1, 3), norm="ortho")
rows, cols = zip(*FREQUENCIES)
values = coeff[:, rows, :, cols].reshape(len(rows), -1)
bins = np.floor(values + 0.5).clip(-61, 61).astype(np.int32) + 61
bins += (np.arange(len(rows)) * N_BINS)[:, None]
counts = np.bincount(bins.ravel(), minlength=N_HIST)
return np.concatenate((counts / 1024, np.asarray(table) / 255)).astype(np.float32)
\end{lstlisting}
\end{minipage}

Массив \texttt{blocks} имеет форму $(32,8,32,8)$. Вторая и четвёртая оси задают координаты внутри блока. После ДКП массив \texttt{values} содержит по одной строке на каждую из выбранных частот. Смещение индексов в \texttt{bins} отводит каждой строке собственный диапазон из 123~ячеек. Поэтому одного вызова \texttt{bincount} достаточно для подсчёта сразу девяти гистограмм.

Ноутбук \texttt{train.ipynb} импортирует определения сетей из того же модуля. В каждом файле весов сохраняются название архитектуры, вероятность dropout, номер выбранной эпохи, обученные параметры, а также средние и масштабы признаков из формулы~\eqref{eq:scale}. Файл \texttt{weights/choice.json} указывает, какие веса программа загружает по умолчанию. После загрузки вызов \texttt{eval()} переводит модель в режим классификации, в котором dropout отключён. При обработке нового JPEG функция \texttt{classify} последовательно вызывает извлечение признаков, стандартизацию и сеть (листинг~\ref{lst:predict}).

\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[language=Python,
 caption={Получение класса и оценки двукратного сжатия},
 label={lst:predict}]
@torch.inference_mode()
def classify(source, detector):
    model, mean, scale = detector
    x = (torch.from_numpy(features(source)) - mean) / scale
    score = model(x[None]).softmax(dim=1)[0, 1].item()
    return int(score >= 0.5), score
\end{lstlisting}
\end{minipage}

\section{Командный интерфейс и проверка работы}

Первый аргумент --- путь к файлу или каталогу. Ключ \texttt{--weights} задаёт веса, ключ \texttt{--csv} --- путь к отчёту. В каталоге поиск \texttt{.jpg} и \texttt{.jpeg} охватывает все подкаталоги. Примеры запуска приведены ниже.

\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[frame=none]
python detector.py data/djpeg/D_363219_68_1078.jpg
python detector.py photos --csv predictions.csv
\end{lstlisting}
\end{minipage}

На тестовой паре с номером фрагмента 363219 выбранная сеть присвоила однократно сжатому файлу оценку~0,104, а двукратно сжатому --- 0,902. При пороге~0,5 оба ответа совпали с исходной разметкой. На рисунке~\ref{fig:pair} приведены сами изображения. По шкале яркости от~0 до~255 максимальная абсолютная разность составила 7~уровней, средняя --- 0,48~уровня.

В отчёт CSV записываются путь к файлу, числовой класс, оценка двукратного сжатия и текст ошибки. Например, для JPEG шириной 128~пикселей в таблице остаётся сообщение об ограничении размера, а поля класса и оценки пусты.

Для проверки пакетного режима программа обработала каталог с 24~тестовыми изображениями, одним повреждённым файлом и одним изображением недостаточного размера. При запуске с весами CNN и с весами MLP ответы для всех 24~допустимых файлов совпали с классами из ноутбука. Разность оценок по модулю была меньше $10^{-6}$ у обеих моделей. Для двух остальных файлов в CSV записаны сообщения об ошибках. Проверка подтверждает, что командная программа применяет те же веса и преобразования, что и при оценке моделей.

\subsection*{Выводы}
Скрипт применяет к файлу те же преобразования и веса, что и ноутбук. При обработке каталога результат для каждого JPEG или причина ошибки записываются в отдельную строку отчёта.
