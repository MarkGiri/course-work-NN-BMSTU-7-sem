# План обучения и сравнительного исследования

## Назначение программы

Предварительная проверка коллекции цифровых фотографий: выделить JPEG-файлы с признаками повторного сжатия для последующего анализа специалистом. Предусмотрена локальная обработка на CPU без обязательного ускорителя. Вход — один файл или каталог; выход — класс и оценка модели для каждого файла, а при пакетной проверке также сводная таблица CSV. Такой результат предназначен для отбора изображений на дополнительную проверку. Двукратное сжатие не доказывает подделку, а однократное не гарантирует подлинность.

Эксперимент нужен для выбора классификатора с учётом ошибок и вычислительных затрат: ложные обнаружения увеличивают список для ручной проверки, пропуски оставляют повторно сжатые файлы невыявленными, время на файл определяет длительность обработки коллекции. Сокращение трудозатрат специалиста является предполагаемой пользой применения; в исследовании измеряются качество классификации и время программы, а не фактический экономический эффект внедрения.

## Исследовательский вопрос

Как изменяются качество классификации и полное время обработки JPEG-файла при замене многослойного персептрона компактной одномерной свёрточной сетью на одинаковых признаках?

План предусматривает самостоятельное обучение обеих моделей с нуля. Результатов обучения пока нет. Указанные ниже размеры выборок и параметры обучения являются начальными настройками; их работоспособность проверяется малым предварительным запуском.

## Область применения

Два класса: `0 = single`, `1 = double`. Основной эксперимент — однородные фрагменты 256 × 256 пикселей с совпадающей сеткой JPEG-блоков. Исключены монтаж, изменение размера, сдвиг сетки между сохранениями и три или более сжатия.

Для большого JPEG программа анализирует центральный фрагмент 256 × 256. Его координаты округляются вниз до кратных восьми: `x = 8 * floor((width - 256) / 16)`, аналогично для `y`. Масштабирование не применяется. Результат относится к выбранному фрагменту; распространение его на весь файл предполагает общую историю сжатия. Для изображения меньше 256 пикселей по любой стороне выводится сообщение об ограничении размера.

## Данные

Основной источник — [набор авторов DJPEG-torch](https://huggingface.co/datasets/plok5308/djpeg_dataset), описание — [страница проекта](https://sites.google.com/view/jspark/home/djpeg). Используются готовые JPEG и их метки, повторное сжатие при подготовке признаков не выполняется.

На 17.11.2026 проверены метаданные архива, его начало и один JPEG:

- архив `jpeg_data.tar.gz`, размер 26 180 076 217 байт, приблизительно 26,18 ГБ;
- LFS SHA-256: `6e58894a5752fbc9afece9b0daacb01f63a6d0704350846105caea8e3512e35a`;
- в начале архива находятся файлы вида `jpeg_data/double/05/D_481065_839_941.jpg`;
- проверенный пример имеет размер 256 × 256, режим RGB и две таблицы квантования;
- [авторский загрузчик](https://github.com/plok5308/DJPEG-torch/blob/master/data.py) использует каталоги `single` и `double`, группы `01`–`18` для обучения и `19`–`20` для проверки.

Прочитаны первые 8 МиБ архива. Полная структура, число файлов, соответствие пар и наличие всех групп ещё не проверены. Семантика числовых частей имени не подтверждена документацией: первый номер похож на идентификатор исходного фрагмента, два последних — на номера таблиц. Использовать эту гипотезу для разбиения можно только после проверки по обоим классам. Номер каталога не следует считать идентификатором фотографии.

Архив сжат gzip, поэтому получить произвольную сбалансированную подвыборку обычным HTTP Range нельзя. Практичный путь — один раз скачать архив или последовательно прочитать весь поток, сохранив только выбранные файлы. Малый размер подвыборки уменьшает объём распаковки и обучения, но не гарантирует уменьшения объёма загрузки. Архив и изображения не добавляются в Git.

### Подготовка выборок

1. Составить список файлов с меткой, группой каталога, размером, таблицей квантования и SHA-256. Проверить чтение JPEG и распределение классов.
2. Проверить правило соответствия файлов `single` и `double`. Создать `source_patch_id` только по подтверждённому правилу. Парные версии одного фрагмента всегда относить к одной части выборки. При невозможности установить пары сначала решить вопрос с идентификаторами, затем формировать итоговое разбиение.
3. Проверить доступность идентификаторов исходных фотографий. Если они есть, группировать по фотографии. Если их нет, группировать по фрагменту и явно указать, что другие фрагменты той же фотографии могут встречаться в разных частях. Тогда тест измеряет качество внутри набора, а не перенос на новые фотографии.
4. Использовать `01`–`16` как кандидатов для обучения, `17`–`18` — для валидации, `19`–`20` — для теста. Если обнаружены пересечения групп по подтверждённым идентификаторам, переразбить целые группы до обучения. Авторское разбиение само по себе не доказывает независимость фотографий.
5. После группировки выбрать до 30 000 обучающих, 5 000 валидационных и 5 000 тестовых примеров; в каждой части поровну двух классов. Если подходящих групп меньше, уменьшить объём и записать фактические числа. Отбор воспроизводимый, `seed = 2026`.
6. Сравнить распределения таблиц последнего квантования между классами. При заметном расхождении сбалансировать их, чтобы метку нельзя было предсказывать преимущественно по параметрам сохранения. Проверить точные дубликаты по байтам и декодированным пикселям; межвыборочные дубликаты удалить целыми группами. Проверка хешей не выявляет все визуально близкие фрагменты.
7. Сохранить один манифест `path,label,split,source_patch_id,source_image_id,sha256`. Не менять тестовую часть после начала сравнения.

Авторы сообщают об особом способе формирования данных: квантование изменялось для яркостной компоненты Y, но не для Cb и Cr. Измеренные значения качества нельзя без дополнительной проверки распространять на произвольные JPEG из редакторов и социальных сетей.

## Общие признаки

Для реализации достаточно Python, PyTorch, NumPy, SciPy, Pillow и scikit-learn для метрик. Версии фиксируются после первого успешного запуска в выбранном окружении. Большая предварительно обученная сеть не требуется.

1. Pillow читает JPEG, яркостную компоненту Y и связанную с ней таблицу квантования. Таблицу нужно выбирать по компоненте файла, а не безусловно брать таблицу с номером 0.
2. Яркостный фрагмент разбивается на блоки 8 × 8. По блокам вычисляется ортонормированное ДКП средствами SciPy.
3. Берутся первые девять AC-позиций в зигзагообразном порядке. DC-компонента исключается. Для каждой позиции строится гистограмма из 121 единичного интервала с центрами от −60 до 60 и двух дополнительных интервалов для значений вне диапазона. Получается матрица `9 × 123`. Частоты делятся на число блоков, поэтому сумма каждой строки равна единице.
4. 64 элемента таблицы яркостного квантования разворачиваются в вектор. Для поддерживаемых 8-битных таблиц значения делятся на 255. Файлы с неподдерживаемой точностью должны отклоняться явно.
5. Для гистограмм вычисляются средние и стандартные отклонения только по обучающей части. Эти параметры сохраняются и одинаково применяются к обеим моделям. Для нулевого стандартного отклонения используется безопасный нижний предел.

Здесь ДКП вычисляется по декодированным пикселям, как в [подготовке входа DJPEG-torch](https://github.com/plok5308/DJPEG-torch/blob/master/djpegnet.py). Эти коэффициенты не равны целочисленным квантованным коэффициентам, записанным в JPEG. Пересчёт по пикселям позволяет обойтись без отдельного JPEG-декодера коэффициентов. Девять AC-позиций, дополнительные интервалы и компактные классификаторы — собственный вариант, а не точное воспроизведение опубликованных архитектур.

Признаки сохраняются в локальный кеш для обучения. При измерении полного времени они обязательно вычисляются заново из JPEG. Для 40 000 объектов массив float32 размером `40 000 × 1171` занимает около 187 МБ без служебных данных; это расчёт объёма, не измерение потребления памяти процесса.

## Модели

| Модель | Структура | Число обучаемых параметров |
|---|---|---:|
| MLP | Объединённый вектор 1171 → Linear 64 → ReLU → Linear 32 → ReLU → Linear 2 | 77 154 |
| CNN-1D | Conv1d(9,16,k=5,p=2) → ReLU → AvgPool1d(2) → Conv1d(16,32,k=3,p=1) → ReLU → AvgPool1d(2) → Flatten; добавить 64 значения таблицы → Linear(1024,32) → ReLU → Linear(32,2) | 35 170 |

Числа параметров рассчитаны по указанным слоям с bias; при реализации их нужно проверить программно. У CNN свёртка идёт вдоль интервалов гистограммы. Длины после двух объединений: 123 → 61 → 30; `32 × 30 + 64 = 1024`.

Сравниваются две конкретные компактные модели при общей информации на входе. Их число параметров различается, поэтому эксперимент не отделяет влияние типа слоя от влияния ёмкости модели. Для поставленного вопроса о качестве и времени этих двух вариантов выравнивание числа параметров не требуется. Вывод «свёрточные сети вообще лучше персептронов» по такому сравнению сделать нельзя.

## Обучение

Начальные параметры для обеих моделей: Adam, learning rate `0.001`, CrossEntropyLoss, batch size `256`, не более `20` эпох. После пяти эпох без улучшения валидационной ошибки обучение прекращается. Сохраняется модель с наименьшей валидационной ошибкой, а не последняя эпоха. Порог класса — `0.5` после softmax; тест не используется для настройки.

Сначала выполняется короткий запуск на 2 000 обучающих примерах и отдельной небольшой валидации. Он проверяет разметку, отсутствие пересечений групп, размеры тензоров, снижение ошибки и примерное время эпохи. Эти показатели не включаются в итоговую таблицу исследования. Если обучение не даёт результата выше случайного уровня на валидации, проверяются признаки и метки до увеличения модели.

После проверки выполнить по три обучения каждой архитектуры с `seed = 17, 29, 43`. Данные, их порядок отбора, правило выбора эпохи и лимит эпох общие. При необходимости менять диапазон гистограмм или параметры обучения решение принимается только по валидации; итоговая конфигурация фиксируется перед тестом.

Сохранить веса, параметры подготовки признаков, конфигурацию, хеш манифеста, seed, журнал эпох и версии библиотек. Длительность обучения и достижимая точность до пробного запуска неизвестны. Ускоритель может использоваться при наличии, но модель и кеш признаков рассчитаны на возможность локального обучения.

## Измерения

Качество: accuracy и F1 для `double`, дополнительно precision, recall и матрица ошибок. Для каждого показателя привести среднее и стандартное отклонение по трём запускам. Для матрицы ошибок выбрать запуск по валидационной ошибке и назвать это правило. На сбалансированном тесте всегда предсказывающий один класс метод имеет accuracy 50 %; это нижняя контрольная точка, а не целевой результат.

Быстродействие измеряется на CPU с одним потоком PyTorch, batch size 1 и моделью в `eval()`/`inference_mode()`. Одинаковое устройство, версии библиотек и входные файлы для обеих сетей. До измерений выполнить 100 прогревочных вызовов. Затем обработать одни и те же 1 000 тестовых JPEG в трёх проходах, чередуя порядок моделей; вывести медиану и 95-й процентиль в миллисекундах.

Основной интервал: открытие локального JPEG → декодирование → признаки → сеть → предсказанный класс. Загрузка весов и запуск Python не входят в него: модель заранее загружена, программа обрабатывает серию изображений. Кеш признаков запрещён. Повторные проходы используют обычный файловый кеш ОС; результат характеризует прогретую систему. Время только сети можно привести отдельно, с явным названием. Между повторами не менять число потоков или устройство.

## Содержание исследовательского раздела

Достаточно шести страниц: условия и данные; настройки обучения; график валидационной ошибки двух моделей; таблица accuracy/F1 и матрицы ошибок; таблица полного времени; вывод о соотношении качества и скорости с ограничениями применимости.

Превосходство CNN заранее не предполагается. Если MLP окажется сопоставим по качеству и быстрее, это самостоятельный результат. Если модели не обеспечат полезного качества, сначала проверяются признаки и данные; таблица заполняется только фактическими измерениями.

## Порядок реализации

1. Проверить полный индекс данных и идентификаторы пар, подготовить манифест.
2. Реализовать единое извлечение признаков, две модели и малый запуск.
3. По результатам малого запуска окончательно зафиксировать архитектуры и написать конструкторский раздел.
4. Реализовать обучение, сохранение модели и команду проверки JPEG-файла или каталога с сохранением результатов в CSV; описать реализацию в технологическом разделе.
5. Выполнить шесть обучений, измерить качество и время, написать исследовательский раздел и завершить введение с заключением.
